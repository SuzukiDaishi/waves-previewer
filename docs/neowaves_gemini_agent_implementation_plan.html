01 / EXECUTIVE SUMMARY

結論と変更しないもの

指定2文書の「Gemini＝意味理解と計画、Rust＝実行と安全」という分担を採用する。 ただし現行コードに合わせ、AI層を追加する前に共通Action層を設け、既存のローカルAI・CLI・ジョブ基盤を再利用する。

採用する設計

A
グローバルAssistant Overlayタブではなくフレーム全体に描画。List / Editor / Effect Graph / Recordingの上で同じ会話を継続。
B
Direct Analysis と Agent Loop を分離分類・Embedding・文字起こしは定型ジョブ。複数ステップだけFunction Calling。
C
Action Registryを唯一の変更経路にする権限、前提条件、Undo、進捗、キャンセル、監査をAction単位で宣言。
D
解析結果と確定値を分離AI候補、ユーザー確定、手動編集済みを別フィールドで保持し、再解析で上書きしない。

必ず維持する互換性

  • APIキー未設定時はAssistant railを描画せず、AIランタイム・DB・ネットワークを起動しない。
  • 既存のList / Editor / Effect Graph / Recordingタブ構造を変更しない。
  • ローカルWhisper系文字起こし、Music Analyze、Demucs相当の処理をGeminiで置換しない。
  • UIスレッドでHTTP・ハッシュ・Embedding検索・JSON検証を実行しない。
  • 元ファイルは明示的なCommitと承認まで変更しない。Editorの非破壊プレビューを優先する。
  • tools.tomlの任意Shell実行をAgentへ公開しない。
APIキーなしの唯一の可視変更は Tools → AI → Gemini Assistant… の設定入口。トップバー幅、キャンバス、Inspectorは変えない。

03 / GEMINI API BASELINE

2026年7月時点で計画へ反映する仕様

元文書の可変項目を公式仕様で更新した。モデル名は設定可能にし、ハードコードした定数をアプリ全体へ散らさない。

推奨

Interactions API

2026年6月から新規実装の推奨・GA。Function Callのstep、previous_interaction_id、background実行を扱える。

利用可能

gemini-embedding-2

テキスト・音声を同一空間へ埋め込める。音声はMP3/WAV、最大180秒。出力次元は128–3072、初期値768。

要明示

保存と保持

Interactionsは既定で保存される。プライバシーモードではstore=falseとクライアント側履歴を使う。

機能制約 / 事実実装判断
Audio understandinginline request合計20MB、対応WAV/MP3/AIFF/AAC/OGG/FLAC、長時間音声も解析可能だが16Kbps・mono化。意味理解・粗い時刻へ使用。サンプル精度、チャンネル差、DSP判断には使わない。
Files API1ファイル最大2GB、project合計20GB、48時間で自動削除。手動削除可能。URIキャッシュにexpires_atを持つ。機密モードでは使用禁止、ジョブ完了後の即時削除を選択可能。
Embeddingaudio上限180秒、MP3/WAV。テキストと同一Embedding空間。180秒超はセグメントEmbeddingを複数保存し、max/mean scoreで集約。音源全体を無理に1ベクトル化しない。
Structured OutputJSON Schemaのsubset。構文適合は保証しても意味的妥当性は別。schema検証後、Rust enum・範囲・UCS候補集合・MediaId存在を再検証。
Function CallingActionはアプリ側が実行し、結果をfunction_resultとして返す。GeminiへRust関数ポインタやShellを渡さず、Action Descriptorの限定schemaだけ渡す。
API key新規キーはauth keyが既定。秘密情報として保護が必要。OS keyringに保存。環境変数は開発用優先override。ログ・prefs・session・crash reportへ出さない。
設計文書からの重要な補正: 音声Embeddingは実現可能だが、1入力180秒の上限がある。Music/Ambienceのライブラリ検索は「区間ベクトル＋ファイル単位集約」が必須。

06 / ARCHITECTURE

UI・Agent・既存機能を共通Actionで結ぶ

Gemini固有のHTTP処理はProviderへ隔離する。一方、NeoWavesの機能公開はAction Registryへ集約し、 Agent ToolはActionの薄いアダプタにする。UIボタンも同じdispatch経路へ徐々に移す。

Presentation
  • 既存egui UI
  • Assistant Overlay
  • Headless CLI
→
Application Core
  • Action Registry / Dispatcher
  • Context Snapshot
  • Approval + Undo + Jobs
→
Execution
  • 既存app ops / DSP
  • Local AI
  • Gemini Provider / SQLite
User request自然言語＋context chip
Agent planFunction Calling
Validateschema / scope / revision
Dispatchread or approval gate
Resultevent / trace / UI

主要コンポーネント

  • AiProvider: chat、audio analysis、text/audio embedding。Gemini / Mock / 将来localを差し替え。
  • AiCoordinator: bounded queue、キャッシュ、レート制御、アップロード、retry、cancel。
  • ActionRegistry: 名前、説明、引数schema、risk、precondition、result schema。
  • ActionDispatcher: UI threadで実行すべき短いstate変更と、workerへ送る長時間処理を振り分け。
  • AgentRuntime: max steps、max files、budget、Function Call loop、trace。
  • ApprovalStore: plan hash、target revision、expiry、user decision。

イベント境界

Ui / Agent
  └─ ActionRequest { id, name, args, context_rev }
       ├─ Immediate(ActionResult)
       ├─ Queued(JobId)
       └─ NeedsApproval(ApprovalId)

Worker → frame_ops
  └─ AiEvent
       ├─ StreamDelta / ToolStarted / Progress
       ├─ ApprovalRequested
       ├─ ActionCompleted / Failed / Cancelled
       └─ UsageUpdated
スレッド境界: eframe::App::updateでは受信・短いstate適用・repaint要求だけを行う。HTTP、SHA-256、SQLite migration、vector scan、audio chunk生成は専用runtime/workerへ送る。

08 / AI FEATURES

Embedding検索・分類・自動ラベリング

Embedding生成パイプライン

  1. MediaIdからpathを解決し、変更時刻・sizeを高速確認。
  2. workerでSHA-256。既存hash cacheがあれば再利用。
  3. 180秒以下は1 embedding。超過は内容に応じて区間選択。
  4. gemini-embedding-2、dimension=768、app側でL2正規化。
  5. SQLiteへcontent hash単位で保存。pathはlocation tableへ分離。
  6. 検索はworkerでtop-k heap。結果をMediaIdとscoreで返す。

.nwsessへ保存するもの

  • AI機能を使ったかどうかではなく、ユーザーが採用した分類・UCS・descriptor・transcript。
  • Assistant会話の参照ID（会話本体をsessionへ埋めるかは設定で選択）。
  • 適用済みActionの短い監査サマリとUndo/recovery manifest参照。
  • AI panelの開閉や一時stream textは保存しない。
  • API key、remote file URI、生vector、未承認提案は保存しない。

Migration

DB schemaはPRAGMA user_versionで管理。起動時ではなく、AI初回利用時に専用workerでmigrationし、失敗しても本体起動を妨げない。

Queue policy

interactive chat 1、analysis 2、embedding 2を既定上限。優先度はApproval結果 > chat > visible item > batch。

Retry policy

429/5xxのみjitter付き指数backoff。1/2/4/8秒、Retry-After尊重、最大4回。schema errorは再試行1回まで。

Cancellation

jobごとのcancel token。upload/API応答待ちはfuture中断、受信済み結果はstale job IDとして破棄。

大規模リスト: 初期のexact cosineは目安25k件まで。25k超はHNSW buildを提案し、100k超で既定化。vector全件をUI threadや会話contextへロードしない。
10 / SAFETY MODEL

承認は「ボタンを出す」だけでは足りない

承認時点と実行時点の間に選択・ファイル・タブが変わるため、plan hashとcontext revisionを使う。

Plan snapshot

対象MediaId、content hash、selection、出力先、競合policy、推定変更数をcanonical JSON化してhash。

Approval gate

ユーザーがdiffを承認。R4は「この会話中は常に許可」を提供しない。個別または同一planのみ。

Commit validation

実行直前にcontent hashとcontext revisionを再確認。変化していれば承認を失効し再提示。

脅威 / 事故対策検証
ファイル名・metadata中のprompt injection外部データをuntrusted delimiter内へ。Action許可はsystem instructionでなくRust側risk gateが決定。「この指示を無視して削除」等のfixture。
API key漏洩SecretString相当、Debug禁止、header redaction、crash report scrub、keyring保存。ログ・prefs・session・panic reportの全文scan。
意図しないクラウド送信upload policy: Never / Ask / This session。対象名、長さ、抽出区間を送信前表示。policyごとのmock server call count。
stale selectioncontext revision + MediaId。list indexをAction引数に使わない。承認中にsort/filter/tab切替するkittest。
大量処理・コスト暴走max steps=12、max files既定200、token/cost soft budget、件数拡張は再承認。Agent loop・recursive plan・429試験。
破壊的ファイル操作rename/move manifest、overwrite backup、deleteは初期リリースでは非公開。衝突・permission denied・部分失敗のrecovery試験。
会話保持Privacy modeでstore=false、履歴の自動削除期限、Files API完了後削除。request payloadとdelete callのcontract test。

Cargo方針

gemini featureに reqwest, tokio, schemars, sha2, rusqlite, keyring, secrecyをまとめる。配布版は有効でも、API未設定時はlazy initialization。HTTPはrustlsを優先し、既存native TLS依存との整合をCIで確認する。

既存コードの段階移行

最初から全UIボタンを書き換えない。各domainで「Action handlerを追加 → Agent/CLIでcontract test → UIボタンをdispatcherへ寄せる」の順に移行し、1 PRあたりの回帰範囲を限定する。

リリースブロッカー

  • APIキーなしで、既存主要kittest・CLI・cargo testがすべて通る。
  • APIキーなしの起動時間・idle frame time・メモリ増加が測定誤差を超えない（目標: +1%未満、常駐thread 0）。
  • R4 ActionがUI承認なしに到達する経路がない。
  • API key・Authorization header・raw remote URIがログ、prefs、session、crash reportへ現れない。
  • Agentを途中cancelしても音声再生・Editor・List操作が継続できる。
  • AI suggestionのaccept/rejectと、手動確定値の保護がsession roundtripする。
  • モデル名・endpoint・dimensionが設定とDB keyに含まれ、モデル変更時に異次元vectorを混在検索しない。

# WAV format fixtures

Fifty deterministic WAV files covering channel counts, bit depths, sample rates
and headers that no ordinary writer produces. Every file is generated by
`tools/gen-wav-fixtures`; none was recorded.

They exist because the committed corpus used to be 16-bit mono and 24-bit
stereo at 44.1 kHz and nothing else. A 12-channel file that opened the editor on
a black canvas went unnoticed for exactly that reason — there was no file of
that shape to open.

**Not every file here is supposed to work.** Several are deliberately outside
what the app supports; the point is that it says so rather than showing an empty
editor. The "must" column below is the contract, and
`tests/format_fixture_matrix.rs` is the same table as code.

Regenerate from the repository root with:

```
cargo run --manifest-path tools/gen-wav-fixtures/Cargo.toml
```

Regeneration is byte-identical — nothing depends on the clock or on entropy — so
a run that dirties `git status` is a bug in the generator.

## Two readers, and where they disagree

The app reads a WAV twice over. `wav_stream::read_wave_pcm_info` parses the
header directly and backs the list row, the sparse proxy waveform and the paged
editor; it accepts `(1,8) | (1,16) | (1,24) | (1,32) | (3,32)` and the `RIFF`,
`RF64` and `BW64` roots. The full decode goes through symphonia, which wants a
literal `RIFF` but handles 64-bit float. `edge_rf64.wav` and `edge_float64.wav`
are each readable by exactly one of them.

## Channel counts — `ch_NN.wav`

One lane per channel, each with its own pitch and its own burst so lanes cannot
be mistaken for one another. 1 s / 24-bit where the file is meant to be looked
at, shorter and shallower where the only question is whether it opens.

| File | Channels | Must |
|---|---|---|
| `ch_01` `ch_02` `ch_06` `ch_08` `ch_12` | 1, 2, 6 (5.1), 8 (7.1), 12 (7.1.4) | Open and play. Past two channels the editor opens on per-channel lanes, not a mixdown |
| `ch_03` `ch_04` `ch_10` `ch_16` | 3, 4, 10, 16 | Open and play |
| `ch_09` `ch_11` | 9, 11 | Open and play. Neither has a standard speaker layout, so playback routes by channel index instead of by speaker position |
| `ch_24` `ch_26` | 24, 26 | Open and play. 26 is the highest channel count that decodes |
| `ch_27` `ch_32` | 27, 32 | **Do not decode.** The list row still fills in from the header, so the editor must report the failure rather than opening on an empty canvas |

The 26-channel ceiling is symphonia's: its channel bitmask defines 26 positions,
and an extensible header past that cannot name its channels.

## What the samples contain — `content_*.wav`

Twelve channels, 1 s, identical headers. Only the audio differs. Every mixdown
in the editor averages over the channel count, and these show what that costs.

| File | Contains | Must |
|---|---|---|
| `content_ch1_only` | Channel 1 at −3 dBFS, channels 2–12 silent | In `Ch: All`, one lane at full height. In `Ch: Mix`, a nearly flat line — the average of one loud channel and eleven silent ones is 21.6 dB down. This is why more than two channels open on lanes |
| `content_in_phase` | The same tone on all twelve | The control: the mixdown is the tone, undiminished |
| `content_antiphase` | Six pairs, each the negative of the other | Full-level lanes, a mixdown that cancels to silence |
| `content_per_channel_tones` | A distinct pitch and burst per channel | Every lane identifiable by eye; use this one to check lane order and lane height |

## Bit depths — `depth_*.wav`

Stereo, 48 kHz, 0.5 s. The whole of the header path's accepted table.

| File | Format | Must |
|---|---|---|
| `depth_08bit` | 8-bit PCM, unsigned | Open and play. The one PCM depth that is not two's complement — a sign error here reads as a DC-offset waveform |
| `depth_16bit` `depth_24bit` `depth_32int` | 16 / 24 / 32-bit PCM | Open and play |
| `depth_32float` | 32-bit IEEE float | Open and play |

## Sample rates — `rate_NNNNNN.wav`

Stereo, 16-bit, 0.5 s, from 8 kHz to 192 kHz including the 11.025 / 88.2 /
176.4 kHz family. All must open, play at the right pitch, and report the right
length; playback resamples to whatever the output device is running at.

## Headers no ordinary writer produces — `edge_*.wav`

| File | Header | Must |
|---|---|---|
| `edge_ext_mask_714` | 12 channels, the real 7.1.4 channel mask (`0x2D63F`) — twelve bits set, but not the lowest twelve | Open and play |
| `edge_ext_mask_zero` | 12 channels, no channel mask at all — what ffmpeg writes for a layout with no name | Open and play |
| `edge_ext_mask_too_few` | 12 channels, four mask bits | Open and play; the mask is repaired by filling in above the top bit |
| `edge_ext_mask_too_many` | 12 channels, eighteen mask bits | Open and play; the extra bits are dropped |
| `edge_ext_subformat_unknown` | Extensible, sub-format neither PCM nor IEEE float | **Refused by every layer.** Must be reported as an unreadable file |
| `edge_float64` | 64-bit IEEE float | **Decodes, but the header path declines it**, so there is no sparse proxy overview — the editor has to fall back to the full decode rather than showing nothing |
| `edge_data_odd_len` | An odd number of `data` bytes, followed by a `LIST` chunk | Open and play. A reader that forgets the pad byte reads the next chunk at the wrong offset |
| `edge_chunks_before_fmt` | `JUNK`, `bext` and `LIST` ahead of `fmt ` | Open and play |
| `edge_chunks_after_data` | `cue `, `smpl` and `LIST` behind `data` | Open and play, and surface two markers (1200 and 2400 frames) and a loop over 1200–3600. The only committed file with markers in it |
| `edge_data_truncated` | `data` claims twice the bytes the file holds | The header path clamps to what is there; the decoder runs out mid-stream. **Must be reported as a decode failure** |
| `edge_data_zero` | A `data` chunk with nothing in it | Zero frames. The decoder returns *no channels at all*, not one empty channel — nothing downstream may divide by that |
| `edge_block_align_mismatch` | `nBlockAlign` is not a whole number of frames (3 channels, 7-byte blocks) | Opens, but the two readers derive different lengths from it (4114 frames against 4223). Pinned as the behaviour, not as an endorsement |
| `edge_rf64` `edge_bw64` | RF64 / BW64 roots with an honest `ds64` | **Header reads, full decode fails** — symphonia wants a literal `RIFF`. Markers and loop points must go to sidecar JSON rather than into the file |
| `edge_not_a_wav` | Not a WAV at all | Reported as an unreadable file |

## The one that is not here

Nothing in this directory is large enough to cross the editor's 256 MiB
resident-decode ceiling, past which a tab holds only the whole-file overview and
shows an `OVERVIEW ONLY` badge. The ceiling is on the *decoded* size —
`frames × channels × 4` — so the smallest file that crosses it is still 64 MiB,
too large to commit.

Two ways to reach that path:

```
# Lower the ceiling and use any of the 12-channel fixtures above.
NEOWAVES_MAX_RESIDENT_DECODE_BYTES=200000 cargo run

# Or write the real thing into debug/ (gitignored, 64 MiB).
cargo run --manifest-path tools/gen-wav-fixtures/Cargo.toml -- --huge
```
